noisestate · best-response dynamics

Reading stability off the first-order condition

The spectral radius the solver reports is not a new object. It is the ratio of cross-curvature to own curvature, and it falls out of the FOC you already write down.

ρ(J) = ρ(D−1O) < 1

Adjustment converges when each agent's own curvature dominates its sensitivity to the others. Everything below is getting to that line and checking it against the solver.

1Where the map comes from

Each agent's objective is quadratic in the strategy profile — that is what makes this an LQG game. So the derivative of agent i's cost in its own strategy gi is affine:

∂Ji∂gi = Hii gi + Σj≠i Hij gj + ci = 0 Hii = ∂²Ji∂gi² is agent i's own curvature. Hij = ∂²Ji∂gi ∂gj is the cross curvature — how far j's strategy tilts i's optimality condition.

Affine in gi means you can solve it. The best response is not an abstract fixed point of anything; it is one linear solve:

gi = BRi(g−i) = −Hii−1 ( Σj≠i Hij gj + ci )

Now differentiate. There is nothing else to do — the Jacobian of the best-response map is read straight off that line:

∂BRi∂gj = −Hii−1Hij   (j ≠ i), ∂BRi∂gi = 0 The diagonal blocks vanish because i's best response does not depend on i's current strategy — it replaces it.

So the whole Jacobian is J = −D−1O, with D the block diagonal of own curvatures and O the off-diagonal cross curvatures.

2Two players collapse further

With a zero diagonal, J² is block diagonal, so the eigenvalues arrive in ± pairs and the radius is a square root:

ρ(J) = √ ρ( H11−1H12 H22−1H21 ) Verified to six digits on both branches below: 0.434208 against 0.434208, and 1.161319 against 1.161319.

The ± pairing is not a curiosity — it is the visible signature of the zero diagonal, and you can see it in the spectra.

3What the condition says

Best-response adjustment is locally stable exactly when ρ(D−1O) < 1: each agent's own curvature must dominate its sensitivity to the others. In the scalar case that reads |H12H21| < |H11H22| — diagonal dominance of the game's Hessian.

This is the standard object under other names: Rosen's diagonal strict concavity (1965), the Jacobian of the pseudo-gradient, best response as a contraction. Nothing here is exotic. It is the operator version of the two-by-two determinant condition, with Hii an operator on the strategy's nodes rather than a number.

4Why the second-order check cannot see it

This is the part worth carrying away, because it explains a live finding in the package.

At window 18 each agent's own problem is still strictly convex. The FOC holds, the second-order condition holds: it is a genuine Nash equilibrium of the truncated game. What fails is the interaction. The own curvatures have collapsed by two orders of magnitude while the cross terms have not, so D−1O runs past 1. Each player is nearly indifferent along some direction, which makes them hypersensitive to the other.

The consequence

The second-order check only ever looks at D. The radius looks at D−1O. They answer genuinely different questions, and the spurious long-window branch is precisely a case where the first passes and the second fails — which is why neither alone identifies it, and why the two flags are now reported together.

5Half of it is already in the code

_second_order builds M = T′GT and takes its extreme eigenvalues by Lanczos. That M is Hii. The diagonal blocks exist analytically today; only the cross blocks are missing, and they are the same construction with the other agent's response operator in place of its own.

So an analytic Jacobian would not be a new derivation. It would be the off-diagonal of an object the code already builds half of — one closed-loop linearisation and one FOC solve per matvec, in place of a full nonlinear best response.

ρ(J) = 0.434208   sqrt(ρ(J₁₂J₂₁)) = 0.434208   diag blocks 0.0e+00
ρ(J) = 1.161319   sqrt(ρ(J₁₂J₂₁)) = 1.161319   diag blocks 0.0e+00

Worth knowing before anyone builds it: the finite-difference route is not the weak link. Sweeping the step over six orders of magnitude, 1e−4 to 1e−9, moves the radius by 1e−4. An exact Jacobian would return the same number — the case for it is cost per matvec and the transpose, not accuracy.

Numbers measured on examples/ch3_two_player.yaml at 24 nodes per panel, noisestate 0.6.9. The full Jacobian is 48×48 — small enough to assemble and diagonalise directly, which is how the block structure and the square-root identity were checked rather than assumed.
